# ANE/GPU GDN experiment — 2026-09-08

Status: implemented, hardware exercised, opt-in. No default change and no remote push.

## Execution graph

The established ANE path evaluates qkv/z/a/b, reads projections onto the CPU,
patches qkv history on the CPU, runs Metal Conv1D/SiLU, reads its result onto
the CPU, then runs recurrence, gating and output projection on the CPU.

With `QWEN_GDN_ANE_GPU_TAIL=1`, a completed ANE request feeds four IOSurfaces
directly into one Metal command buffer:

1. GPU gather of spatial column zero into contiguous projection scratch.
2. Existing Conv1D + recurrent update + gated RMSNorm shader.
3. Existing BF16 output-projection shader.

The recurrent and convolution state use the model's existing aligned shared
allocations. Only the final hidden vector is copied back. Hyper-connection,
routing, and expert planning remain on their existing paths.

ANE evaluation still completes on the host before this command is submitted.
This integration removes CPU tensor materialization; it does not yet eliminate
the ANE completion round-trip or demonstrate ANE/GPU compute overlap in decode.

## Ownership and failure handling

The Metal continuation retains IOSurfaces through command retirement. The
GDN pending ticket pins its native layer context; model teardown drains active
commands before Rust-owned backing can be freed. Pre-submit decline restores
the scalar path from the completed ANE outputs. Post-submit failure is fatal
because recurrent state may already have changed.

The smaller Conv1D wrapper also has an owning split-phase ticket with
draining Drop, and retains the backing IOSurfaces rather than only no-copy
MTLBuffers. Its regression fixture drops original surface wrappers, submits,
drops the pending ticket, and verifies results. It passed with maximum
absolute error about 4e-9 against the scalar Conv1D reference.

## Private shared-event hardware probe

`logan-ane/examples/shared_event_probe.m` validates method type encodings at
runtime and uses a ten-second process watchdog. Host signal and delayed-host
wait modes passed. The Metal mode also passed:

GPU producer → shared event → ANE identity projection → shared event → GPU copy.

Both Metal command buffers were submitted before waiting for ANE completion;
the GPU-consumed output had zero error. One observed ANE submit took 0.125 ms.
This is not an inference latency result: the fixture intentionally retains
objects until process exit, and its elapsed time includes a delay after completion.

Verified event factories on this M2:
- `_ANESharedEvents sharedEventsWithSignalEvents:waitEvents:`: `@32@0:8@16@24`
- `_ANESharedSignalEvent signalEventWithValue:symbolIndex:eventType:sharedEvent:`: `@44@0:8Q16I24q28@36`
- `_ANESharedWaitEvent waitEventWithValue:sharedEvent:`: `@32@0:8Q16@24`

Signal eventType=0, symbolIndex=0 worked for the one-output fixture.
The Metal event's `IOSurfaceSharedEvent` getter returned the shared backing.
Adding sharedEvents makes ANE evaluate return before completion. The request
must have a completion handler: live arm64 disassembly established the callback
as `void (^)(BOOL, NSError *)`. Omitting it caused a callback-thread crash in
the exploratory probe.

Do not add sharedEvents to the current synchronous Rust evaluate API. A
production ANE pending owner still needs model/request/surface/block retention,
multi-output event qualification, reuse, cancellation, and timeout recovery.

## Reproduced cache bug and fix

Persistent MIL/weights under `~/.cache/logan/ane` did not redirect Apple's
hard-coded compiler input lookup under NSTemporaryDirectory/<descriptor>.
A native cache miss therefore failed with `verifyBundleAtPath: invalid model`;
all 36 ANE layers could fall back while old cache.meta files still said hit.

The fix stages source inputs in the framework-required temporary directory
on a native miss and keeps the Logan persistent cache in its existing location.
These temporary compiler inputs are not claimed to be compiled programs.
Per-model `native_cache_hit()` is now printed on successful GDN warmup.

`persistent_cache_probe` forced a native miss with persistent inputs, evaluated
exact ReLU outputs, then verified a true native warm hit with exact outputs.
The model run after repair compiled all 36 islands; the next process reported
native hits. Warm startup still performs BF16→FP16 repacking and descriptor
materialization. Native-cache-hit load failure recovery and concurrent cache
mirror hardening remain separate work.

## Measured runtime and interpretation

Runs were sequential on the M2, using six fixed-token recurrent forwards.
The warm summaries below exclude positions 0 and 1 and use positions 2–5.
Order: GPU tail (native compile misses), ANE baseline (native hits), GPU tail
again (native hits), then Metal-only control. Browser/GPU and background
activity were observed; no unrelated applications were stopped.

| Path | Warm median s/token | Warm range s/token | GDN median ms/token | Startup s | First forward s |
|---|---:|---:|---:|---:|---:|
| Activated ANE baseline | 13.89 | 12.59–17.70 | 4567 | 43.91 | 35.91 |
| ANE GPU tail, first run | 13.36 | 12.74–14.05 | 4002 | 55.30 | 31.13 |
| ANE GPU tail, repeat | 17.15 | 14.25–19.80 | 4502 | 53.31 | 33.89 |
| Metal-only control, severely stalled | 48.07 | 43.10–72.22 | 20355 | 12.45 | 41.47 |

The observed ANE-baseline throughput was about 0.072 tok/s; GPU-tail runs
were about 0.075 and 0.058 tok/s (inverse median latency).
**No stable end-to-end throughput improvement is established.** The Metal-only
control is not representative of the previously optimized best Metal runs,
so its severe stalls do not justify a default change.

The first GPU-tail run exposed 2221 ms/token of native GDN host wait for
56 ms/token of GPU execution; its repeat exposed 2686 ms for 51 ms execution.
The Metal-only control exposed 20349 ms for 105 ms execution. These are
host-wait intervals, not proof that the GPU was idle or that a particular
portion is synchronization overhead; residency, queueing and system contention
remain possible contributors.

GPU-tail logits were bit-identical between its two six-forward runs. Its
measured CPU map count was 36/token in both runs, compared with 252/token
for the activated ANE baseline. That data-movement reduction, the cache fix,
and the standalone device-event proof are the concrete outcomes retained here.

Remaining work: use the qualified event mechanism through an owning ANE
pending request, qualify all four outputs and cancellation, then connect its
completion event directly to the GPU tail. Separately isolate residency/queue
waits under controlled machine conditions. CPU hyper-connection/routing and
BF16→FP16 startup repacking remain outside this change.

## Numerical results

Six deterministic recurrent forwards compared the GPU tail against the
activated ANE baseline:

- All six argmax tokens and all top-10 sets matched.
- Minimum cosine: 0.99999935948.
- Maximum relative L2: 0.00114710 (0.11471%).
- Maximum RMSE: 0.00264366; maximum absolute logit difference: 0.0127403.
- Worst top-50 overlap: 49/50; worst top-100 overlap: 99/100.
- These paths are not bit-identical.

The existing ANE baseline itself diverged more strongly from the BF16 CPU
fallback after forward 4: relative L2 7.741%, cosine 0.997006, top-10 9/10,
top-100 94/100, with unchanged argmax. The GPU-tail path showed the same
large divergence pattern (7.757%). Expert routing counts also changed at that
point. This is not a new quantization experiment, and the result does not
establish general quality safety for the existing FP16 ANE projections.

## Synchronization and CPU data movement

Scope: the 36 GDN layers per decode token, excluding other model operations.
Success-path trace counters and source contracts establish:

| Metric | ANE baseline | ANE + GPU tail |
|---|---:|---:|
| ANE submissions / host completions | 36 / 36 | 36 / 36 |
| GDN Metal command buffers / host waits | 36 / 36 | 36 / 36 |
| ANE→Metal handoffs | 36 | 36 |
| CPU IOSurface maps | 252 | 36 |
| Projection + Conv1D output bytes materialized on CPU | 3,847,680 | 0 |
| Conv history bytes staged by CPU | 4,423,680 | 0 |
| Final GPU-tail output bytes copied to CPU | 0 | 368,640 |

The input surface writes are unchanged. The GPU gather is a device-side copy,
not an alias; projection bytes never pass through host vectors on the successful
tail path. The table excludes CPU arithmetic traffic through recurrent state.
No new speculative expert prefetch or MetalIO overlap policy was added.

## Reproduction and artifacts

Build `gdn_ane_e2e`, `gdn_ane_greedy`, and the two Rust probe examples in release
mode. Build the Objective-C probe using the command in its file header.

Use the existing
`/Users/mateo/models/Qwen3.8-Flash-Next-REAP-288-MXFP4-Apple8.coli`.

Enable with `QWEN_GDN_ANE=1 QWEN_GDN_ANE_LAYERS=all QWEN_GDN_ANE_GPU_TAIL=1`.
The tail flag defaults off; ANE still defaults off. Existing layer selection
and fallback behavior are retained. `QWEN_GDN_ANE_TRACE=1` now reports
submission/evaluate timing and CPU map/byte counts.

`LOGAN_LOGITS_EACH=<prefix>` optionally captures each deterministic forward's
logits. Captures are buffered and occur outside the timed forward.

Raw logs, per-forward logits, comparison JSON, and sequential runner scripts:
`.perf_runs/ane_async_20260908/`.
The original `ane_base` and `ane_tail` runs were invalid ANE benchmarks because
warmup failed; only the former's known BF16 fallback logits were used as an
additional numerical reference. Performance comparisons use activated runs.

The paired ANE-baseline text run was stopped at the user's request to wrap up
